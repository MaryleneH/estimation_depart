# Organisation du code R

Les règles métier que ce code doit garantir sont décrites dans `specs/` (spécifications en Markdown avec scénarios Gherkin, identifiants `SPEC-*`, matrice de traçabilité vers les scripts et les tests). Avant de modifier une règle, modifier d'abord la spec concernée (voir `specs/09_matrice_tracabilite.md`).

Le point d’entrée reste `main.R` à la racine : `source("main.R")` lance toute la chaîne. Les scripts communiquent par les objets de la session, pas par des fichiers intermédiaires.

Règle de lecture : **le préfixe d’un répertoire est le numéro du premier script qu’il contient**, donc l’ordre alphabétique des répertoires est l’ordre d’exécution. Les noms de scripts, avec leur numéro, n’ont pas changé lors de la mise en sous-répertoires.

## Typologie des territoires (08f, specs/10)

Couche d’analyse **en aval** du 08d : lit la table département × grande CS exacte (`departs_cs1$analytique$departement`) et le stock tous âges (01c), ne recalcule aucun départ. Par département : poids (part de l’emploi BITD national, base = emploi actuel tous âges si disponible), structure par grande CS (« Dominante X » si la première CS atteint `TYPO_SEUIL_DOMINANCE_CS`, sinon « Mixte »), volume (`departs_central/bas/haut`), intensité du renouvellement (`part_a_remplacer_pct` = départs / emploi actuel ; repli `taux_depart_central_pct`), concentration des départs sur une CS, CS au plus gros volume et CS à l’intensité la plus forte, puis un profil attribué par règles ordonnées (fort enjeu, risque émergent, renouvellement concentré, pôle stable, implantation diffuse, cas à expertiser) avec une justification textuelle déterministe. Seuils dans `00_config.R` (`TYPO_*`) ; classes par terciles = règle de classement statistique **provisoire**, bornes écrites dans `parametres_typologie.csv`. Sorties : `interne/` (complet, jamais versionné) et `diffusion/` (secret du département, masque des cellules, variables dérivées masquées dès qu’une cellule CS l’est). Les tensions DGA / France Travail (FAP × bassin) sont une couche séparée : jamais attribuées au département, jamais alimentées par les départs départementaux, aucune correspondance FAP → grande CS (gabarit `data/templates/tensions_fap_territoires_template.csv`, lignes fictives).

## Arrondi des restitutions

Les calculs sont conservés à leur précision complète. Les nombres attendus de personnes sont arrondis à l’entier uniquement lors de la restitution ; les taux sont calculés sur les valeurs exactes. Convention unique dans `00g_format_restitution.R` : personnes → entier (demi vers le haut : 0,5 → 1, 2,5 → 3, 27,5 → 28, comme Excel ; `round()` de R arrondit au pair et n’est pas utilisé pour les personnes), taux → une décimale, codes et effectifs observés intacts, NA conservé (secret : jamais 0). Quand un total et ses composantes sont affichés ensemble (départs = retraite + invalidité + décès ; « Ensemble » = Σ catégories d’une fiche), les composantes sont arrondies par la méthode des plus forts restes pour sommer exactement au total affiché (restes égaux : la plus grande composante d’abord). Les territoires sont arrondis indépendamment : Σ départements affichés peut différer de la région affichée, jamais d’ajustement artificiel. Ordre : calcul exact → contrôles exacts → secret statistique → arrondi de restitution → CSV, HTML, fiches, cartes.

## Cartographie des départs

`08e_cartes_departs.R` lit uniquement les six tables de **diffusion** (`sorties/departs_pcs/diffusion/`, `sorties/departs_cs1/diffusion/`) et écrit `sorties/cartes_departs/{pcs,cs1}/carte_<dimension>_<niveau>.html`. Région et département : carte choroplèthe interactive (vue « Résultats » par PCS ou grande CS avec indicateur au choix, vue « Diffusabilité »), plus un `.png` de la vue initiale. **France entière : tableau de bord national de chiffres clés** (départs estimés, taux, salariés dans le champ, fourchette basse / centrale / haute, composition par cause), sans carte, puisqu’une valeur nationale ne varie pas entre territoires. Chaque page est autonome (SVG inline, JavaScript natif, aucune ressource externe). **Lisible sans JavaScript ni CSS** : les passerelles de messagerie retirent souvent les scripts (parfois les styles) des pièces jointes HTML, et un tracé SVG sans attribut `fill` est noir ; la vue initiale (vue « Résultats », première catégorie, part des salariés, estimation centrale ; tableau de bord : première catégorie) est donc calculée en R (`vue_initiale_carte()`, ports fidèles des règles de classes du JS) et écrite dans le HTML : attributs `fill` / `stroke` de chaque territoire, légende, en-tête, liste des catégories, chiffres du tableau de bord. Un bandeau « Version statique » reste visible tant que le JavaScript ne l'a pas masqué. **Version courriel** (`CARTES_COURRIEL`, fichiers `carte_<dim>_<niveau>_courriel.html`) : aucun script, pas même le bloc JSON, donc rien que la passerelle interministérielle SISMEL puisse retirer ; toutes les catégories sont précalculées en R, le changement de catégorie est fait en CSS pur (boutons radio, sélecteur `:checked`), les infobulles sont les `<title>` natifs du SVG, la géométrie est écrite une fois et réutilisée par `<use>`. Un seul indicateur (part des salariés, estimation centrale) ; les infobulles donnent salariés, départs, fourchette et part. C'est cette version qu'il faut joindre aux envois externes.

**Langage public.** Les pages sont écrites pour un public non statisticien : « Salariés de 45 ans ou plus », « départs estimés d’ici 2030 », « pourraient partir d’ici 2030 », « Résultat non diffusé — secret statistique », « Aucun salarié observé », « Où peut-on afficher les résultats ? » ; ni « champ », ni « effectif », ni nom de variable. Les phrases qui dépendent de l’âge viennent de `construire_libelles_public()` (00f) et suivent `AGE_MIN_BTS`. **Qui est concerné ?** est rappelé en permanence (en-tête de chaque page, KPI, légendes, pied) et construit par `construire_libelle_champ()` (00f) depuis la configuration réelle : `AGE_MIN_BTS`, `PCS_VERS_CS1`, `PCS_HORS_CHAMP`, périmètre SIREN BITD, année de référence et horizon. Il n’est jamais écrit en dur. Les libellés d’interface viennent d’une seule table, `LIBELLES_UI` ; aucun nom de colonne R n’apparaît à l’écran. **Libellés des PCS** : `charger_libelles_pcs()` (00f) lit la nomenclature locale `data/PCS-ESE_2017_Liste.xlsx` (`FICHIER_PCS_LIBELLES`, `PCS_LIBELLES_COLS` dans 00) ; une PCS présente dans la nomenclature s’affiche « Libellé · PCS code » (en-tête, infobulle, tableau de bord) et « code — Libellé » dans la liste ; sinon « PCS code · grande catégorie ». Fichier absent = message, jamais d’arrêt. **Ordre de la liste des PCS** : départs estimés (centrale) diffusés, sommés sur les territoires de la carte, décroissants ; PCS sans aucun résultat diffusé en fin de liste ; la première PCS affichée est donc la plus concernée. Les grandes catégories (cs1) gardent l’ordre des codes. **Gris = non diffusé, secret statistique** ; **blanc pointillé = pas de donnée observée** ; une cellule masquée n’embarque que son statut, jamais sa valeur. **Contours** : une seule source, `STYLE_CONTOURS_CARTE` (00f), pour les quatre cartes, le SVG et le PNG : limite entre territoires en gris moyen-foncé fin (lisible sur toutes les classes, sur le gris du secret et entre territoires masqués voisins), limites régionales plus foncées et plus épaisses par-dessus la carte départementale, territoire survolé redessiné en trait sombre au-dessus de ses voisins ; épaisseurs en pixels écran (`vector-effect: non-scaling-stroke`), réduites sur mobile. Fond local `data/cartographie/` (IGN Admin Express via france-geojson, voir `data/LISEZMOI.txt`), métropole en Lambert-93, DROM en encarts. Relançable seul après la chaîne : `source("R/08_territoires/08e_cartes_departs.R")`.
